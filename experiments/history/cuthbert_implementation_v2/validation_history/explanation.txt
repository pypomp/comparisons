Initial validation compared the IF2 process subkey against the native PF parent key. IF2 splits each propagation key into parameter-noise and process keys even when the perturbation scale is zero. The validation reference must use split(key)[1] for the process. Correcting the reference changes no estimator code, tolerance, model, data or experiment. The initial mismatch is retained here.

The captured-scale failure exposed an implementation bug, fixed in _estimation.broadcast_tree and covered by two regression cases. separate_endpoint_score.py records the next validation attempt: native PF scoring with a captured endpoint differed from the public API. The final script keeps that measurement in score_compilation_diagnostic and separately checks native PF scoring with the endpoint passed as a dynamic argument. The endpoint, scoring keys and tolerances were unchanged. No cross-compilation bitwise agreement is claimed.
