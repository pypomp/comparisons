# Formal supervised maze comparison

The user selected native PyDPF DPF, native StopGradientDPF and the added alpha=0.97 derivative correction. This tests supervised robot localization, not likelihood maximization, IF2 or IFAD. The distribution may resemble the presentation of the Dacca figure, but the horizontal axis is held-out position RMSE and lower is better. No method ordering is assumed.

The design has six initializations and two independently seeded training repetitions, paired across three methods: 36 fits. The original 100 epochs, 100 particles, 100 observations, minibatch size 64, networks, supervised loss and AdamW settings are retained. Each complete fit has 1,500 updates, including its B4 tail batch. Strict deterministic execution and the previously measured FCNN-only execution wrapper apply equally to all methods after GPU validation.

The fixed split has 900 training, 400 validation and 700 test trajectories. Unlike the author's global preprocessing and the earlier pilot, image mean and standard deviation are estimated from training images only. The model equations and architecture are unchanged. The same original ordinary PF evaluates validation and test position errors. Validation chooses the best epoch (earliest on ties); three independent test PF streams evaluate that checkpoint once. The test set does not choose epochs, alpha, learning rates or methods. Repetitions share the test set, so 36 fitted models are not 36 independent datasets.

The primary result is final-time localization RMSE in original maze coordinate units, using all 700 test trajectories and three PF streams. Retain per-trajectory predictions, truths, errors, IDs and all three stream results. Report incomplete fits and missing test results explicitly; if a prior validation checkpoint exists after a failed fit, score it once and mark it incomplete. Do not retry failed fits or display only winners.

Native code comes from upstream commit a7487ce1c344c70e1a244e75725b950deb15e146. Only the added-alpha arm imports the previously validated candidate package. The 20 previously recorded original native/model/worker files and FCNN graph implementation are copied without changes. `training_graph.py` routes B64/B4 training to that implementation and all inference to the original method. The correction discounts inherited resampling-weight derivatives; this comparison does not establish a general mathematical identity for all DMOP formulations.

The new scope is bounded by 30 GPU hours. One 1,200-second bridge allocation must pass saved-data source, full-shape forward/gradient/optimizer/RNG and cost audits before the 36 formal tasks can be submitted, each once, with a 2,700-second limit and at most three concurrent tasks. Their maximum reserved sum including the bridge is 98,400 seconds (27 hours 20 minutes). The old diagnostics and their failures remain separate. A failed bridge does not authorize an automatic retry, a cheaper configuration or a larger budget.

The saved audit runs only Torch CPU tensor comparisons/statistics. It never invokes models or optimization. CPU fixtures test all three optimizer chains and the real checkpoint-selection/evaluation driver on T100/J8 samples; they are not GPU or formal results. The first CPU chain exposed aliasing of optimizer checkpoint tensors in the comparison harness. Deep-copying optimizer state before restore fixed the harness; the failed raw records and old source remain retained, with no tolerance change.

No old Dacca/maze job is submitted, polled or collected by this scope. No external publication or Git push is authorized. All new immutable source, raw records, failures, environment and source/terminal checksums must be archived and restored before final delivery.
