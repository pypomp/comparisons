The three methods are local IF2/DMOP/ADPF extensions using PFJAX particle-filter/resampling facilities. The completed run therefore does not establish superiority over a working native OT optimizer.

IFAD uses175 IF2+400 alpha.97 updates. DirectADPF uses425 alpha1 updates without an IF2 prefix and with a different gradient stream. This is not a common-prefix experiment isolating alpha; IF2 initialization, iteration allocation, and alpha all differ. The old protocol comparison sentence about every continuation sharing an IF2 prefix/gradient stream is inapplicable to this three-group run; the executable and scope_notes correctly describe the actual groups. 3. Random-key issue
protocol.json uses gradient_seed91433 and evaluation.seed91434. run.py assigns directADPF gradient_seed+1, also91434 (line131). IF2's score_index is sid*100+rep (line134). Its evaluation rowkey is therefore exactly the directADPF training root key for the same start/repetition (lines89,95). The evaluation stage0 key also equals directADPF update0 key, and actual JAX checks confirm overlap of the first36 split subkeys.

The original IF2 scoring stream remains independent of IF2's own fitting stream, which uses seed91431. This issue alone does not establish biased single-point IF2 scores. However, scoring is not independent of every method's training, so IF2 evaluation noise and the directADPF fitted endpoint can be related. It is inappropriate to claim fully separate training/evaluation streams across the comparison. The correction preserves all fitted endpoints and old scores and re-scores every endpoint with a separate frozen seed.
