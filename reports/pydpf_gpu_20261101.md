# PyDPF GPU repeatability diagnosis

Job 65151857 completed on gl1516/A40 with exit `0:0` and 306 seconds of allocation time. It was collected once after stopping. Collection verified 80 referenced source files, 132 transferred files and 126 terminal-manifest entries. The review reread all 120 NPZ files, recomputed 648 stored array comparisons, and checked all 400 original/candidate cross-repeat gradient pairs. [Audit](../results/pydpf/gpu_diagnosis_audit.json).

The diagnostic uses a small linear model with five observation entries, 24 particles and two batches. It compares the unchanged original `StopGradientDPF`, the candidate default and the candidate with explicit alpha=1, in float32/64 with multinomial/systematic resampling. Each calculation is repeated five times with the same random generator seed.

|---|---:|---:|
| Default, float32 multinomial | 30/50 | 2.384185791015625e-7 |
| Default, float64 multinomial | 35/50 | 2.7755575615628914e-17 |
| Default, either precision, systematic | 100/100 | 0 |
| Deterministic mode, all four cases | 200/200 | 0 |

All forward outputs and final RNG states agree exactly. In default mode the original float32 multinomial calculation itself also varies across repeats. With deterministic algorithms enabled, all within-function repeats and all original/candidate gradient pairs agree exactly. The comparison used the original exact-equality criterion throughout; no tolerance was widened.

This control supports GPU execution nondeterminism as an explanation of the small-fixture exact-equality failure. It does not identify the precise GPU kernel, establish complete Dacca gradient correctness, or measure the performance of deterministic full-scale optimization. Production source and settings were not changed, and no formal fit was run.
