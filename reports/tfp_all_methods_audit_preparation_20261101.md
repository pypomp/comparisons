# TFP three-method audit preparation

The 17:57 UTC scheduler query shows TFP A/B/C jobs 65177155, 65177156 and 65177157 still running. PyDPF A/B/C jobs 65177901, 65177902 and 65177903 remain pending for priority. Neither package has a newly collected gradient result. All six jobs were already submitted; this work made no cluster changes.

`audit_tfp_all_methods_v4.py` is prepared outside the frozen experiment. It requires all three real phase collections and their passed saved-data audits. It repeats the completed physical-prefix audit and each phase audit, then checks all 36 method/start/repetition identities, B/C's 95 initial parameter and zero-Adam arrays, the shared learning-rate file, call counts, failure records and independent raw-score summaries. It counts the physical prefix allocation once and adds the three actual Slurm elapsed values against the original 72,000-second formal budget. The earlier 2,336 validation seconds remain separate. The B12 batch cost is not multiplied by twelve, and A/B workloads remain different.

Additional metadata checks require complete transfer and terminal file lists and hashes, the expected jobs and nodes, one scoring attempt, the saved exclusive launch guard, the original physical prefix and the 16,800-second phase limits. Missing or interrupted phases require partial review; they cannot produce this complete aggregate audit. Actual collection schemas still require review after the jobs stop. No stopped phase was collected again.

The key check reconstructs 11,724 planned TensorFlow call-root/member tuples: 2,100 IF2, 4,800 A, 4,800 shared B/C, twelve prefix warmups and twelve gradient-warmup tuples. B/C training keys deliberately match, as do the three gradient warmup streams. Planned calls are distinct from calls actually reached after early failure. Successful runtime keys and every internal random draw were not separately recorded. JAX endpoint/chunk/repeat scoring keys are checked for uniqueness in their own generator; the audit does not claim that TensorFlow and JAX share a key space or certify independent internal draws.

Preparation used existing saved small-run records and explicitly synthetic phase, score and scheduler metadata. Thirty corrupted copies were rejected: fifteen pairing/key/identity/failure/floor/cost changes and fifteen allocation/file/guard/scoring-attempt changes. The synthetic 36 score records contain 2,808 values and 2,922 JAX keys, with floor, low-ESS and nonfinite cases retained. These are control fixtures, not new Dacca endpoints. Missing real phase audits refuse output. No PF, IF2 or optimizer step was executed.

The archive contains both frozen TFP revisions, the already audited stopped prefix, common scoring source, saved controls and auditor dependencies. Every member hash passed; extraction and rerunning the saved-data controls reproduced 67 JSON files byte for byte. All 7,395 protected source files remain unchanged. Mathematical gradients and missing successful intermediate proposals are not certified by these checks.
