# GPU queue, 1 November 2026

At 02:28 UTC, Cuthbert v3 was running on an A40 in gl1516. It started at 02:26:40 UTC (22:26:40 EDT on 31 October). The other three checks were pending. Slurm reported `Priority` and gave no estimated start time.

| Check | Existing job | State at 02:28 UTC | Start time |
|---|---|---|---|
| Cuthbert v3 | 65144479 | Running, gl1516 | 02:26:40 UTC |
| PFJAX diagnosis | 65151851 | Pending, Priority | Not estimated |
| PyDPF diagnosis | 65151857 | Pending, Priority | Not estimated |
| TFP diagnosis | 65151858 | Pending, Priority | Not estimated |

The pending jobs had no dependency or hold. Higher-priority jobs were present in `spgpu`; the account had no running jobs in the inspected query. The observed reason was not an account GPU limit. `Priority` is one scheduling reason, not a complete explanation of every resource constraint. [Slurm job reasons](https://slurm.schedmd.com/job_reason_codes.html).

Available GPUs did not necessarily come with enough unallocated CPU and host memory. In the first snapshot, gl1516 had three unallocated GPUs, eight unallocated CPUs and 59,750 MiB of unallocated host memory. It could fit a 48 GiB request but not our original 80 GiB request. In the next snapshot no node simultaneously had one free A40, four CPUs and 48 GiB available. These are changing resource snapshots, not reservations or promises of an immediate start.

We reduced the host-memory request on the four existing jobs from 80 to 48 GiB with `scontrol update`. Previous related checks had batch-process peak host memory between 1.7 and 5.1 GiB; 48 GiB leaves more than nine times the largest measured value. The new checks are not identical workloads, so their actual memory use will still be reviewed. Host memory is distinct from GPU memory.

The update preserved each job ID, submission and eligibility times, account, partition, A40 request, four CPUs, time limit, command and working directory. No job was resubmitted. Cuthbert started after the adjustment; the observations alone do not establish how much of its wait was caused by the memory request.

Slurm's requested billing amount fell from 30,131 to 18,078 per job, about 40%, while the GPU-hour limits stayed unchanged. This is a reduction in the requested billing rate, not a measurement of total cost or runtime. Great Lakes charges for requested resources and actual running time. [Great Lakes rates](https://its.umich.edu/advanced-research-computing/high-performance-computing/great-lakes/rates).

The original frozen submission scripts still specify 80 GiB. The scheduler override is retained separately with the before-and-after records. All 1,442 protected Cuthbert files match their previous hashes. The checks' scientific settings and numerical tolerances were unchanged. GPU model, account and time limits were retained; changing them would require separate comparability or runtime justification.
