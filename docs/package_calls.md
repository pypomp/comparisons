# Package calls and additions

This table describes the current candidate interfaces under `packages/`. They differ from the earlier experiment drivers. The [earlier call table, in Chinese](../reports/package_calls_legacy/table_CN.txt) records those historical implementations; their complete sources are preserved in the corresponding reproduction archives. [Chinese supplementary notes](package_calls_CN.md) are also available.

Dynamax is excluded from the main comparison. No further Dynamax implementation or experiments are planned. Its entries in older tables are historical records.

The candidate sources, corresponding original sources and actual experiment drivers were checked again in the [31 October 2026 source audit](../reports/native_pf_audit_20261031/report.md). [Source locations](../reports/native_pf_audit_20261031/source_locations.md) link to the inspected calls. Earlier PFJAX IF2 used a locally written PF time loop; the new interface calls the original full PF. Current Cuthbert uses an added time loop over the original update functions.

| Package | Original package functions used | Code added or modified locally | Parameter optimization |
|---|---|---|---|
| Cuthbert v3 | Original PF update functions returned by `particle_filter.build_filter`; original resampling functions; original `stop_gradient_decorator` at α=1 | Joint state and parameter storage, perturbations, cooling and outer IF2 iterations; new `scan_final` time loop calling original `filter_prepare` / `filter_combine`, rather than the top-level `cuthbert.filter`; new `dmop.log_likelihood` and gradient discounting for α<1 | The formal driver calls the new IF2 and `dmop.log_likelihood`, with external Optax `scale_by_adam`; it does not call the complete `ifad.fit` interface |
| PFJAX v2 | The full original `particle_filter` time loop and `resample_multinomial`; our Dacca model is called through `pf_init` / `pf_step` | An `initial_particles` argument to the original PF; `iterated_filter` wraps states and parameters, applies perturbations and cooling, and repeats the original PF; `particle_filter_mop` adds a resampling gradient correction, including at α=1 | External Optax Adam. The α=1 correction is also added code, not PFJAX's native optimal-transport method |
| PyDPF v1 | Original `ParticleFilter`, `SIS.forward`, `FilteringModel`, resampling and likelihood calculations; the existing `StopGradientDPF` correction | New `IteratedFiltering` model wrappers jointly resample states and parameters, retain the full parameter population, and add perturbations and cooling; an `alpha` argument to `StopGradientDPF` / `StopGradientResampler` | An external `torch.optim.Adam` loop, not a pre-existing package MLE interface |
| TFP v1 | Original `sequential_monte_carlo`, `SequentialMonteCarlo.one_step`, `WeightedParticles` and resampling; the existing differentiable `particle_filter` | New `iterated_filter` wraps parameterized models and repeats the original SMC loop; a new `gradient_discount` argument is passed from `particle_filter` to SMC and applied to weight derivatives | An external Keras Adam loop; no monthly transition density is invented |
| particles v1 | Original `SMC.run` time loop, `Bootstrap` model calls, resampling and `logLt` | New `iterated_filtering` and `_PerturbedBootstrap` carry parameters with states, apply perturbations and cooling, and pass the full parameter population between iterations; existing Python files are unchanged | New experiment A uses the original PF with external SciPy Nelder–Mead; B first uses the new IF2 and then the same external optimizer |
| PyPOMP | Earlier paper experiments call `functional.mif`, `functional.train` and its Adam implementation; endpoint evaluation calls the fixed original PF | Model code, parameter settings and experiment orchestration; no new PyPOMP public interface is claimed here | Package optimization and independent PF evaluation are recorded separately |
| pypfilt | Earlier experiments call `pypfilt.fit` to run the original PF | Dacca model callbacks, likelihood-increment recording, external optimization and experiment records | External SciPy Nelder–Mead; this experiment does not compare native IF2, IFAD or a native MLE interface |

An added public interface is a function in the local candidate code. It does not imply that the pinned original version provided it or that upstream authors have accepted it. Each candidate package includes the full patch, source locations and checks of unchanged original code.

Final optimization scores come from the frozen original PyPOMP PF, separately from training losses and perturbed IF2 likelihoods. Small API examples may use a package's own PF for checks; those checks are distinct from the independent evaluation of formal optimization endpoints.
